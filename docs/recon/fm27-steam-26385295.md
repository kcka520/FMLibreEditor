# FM27 Steam build 26385295 (27.0.1, the full release)

Observed on 10 November 2026 with the Steam install under `D:\SteamLibrary\steamapps\common\Football Manager 27\`
(app 4530370), minutes after the update to the full release. The save, of 16 August 2026 (47,896 players, 23,922 staff
and 29,740 clubs), had been read in full on build 26340721 the same day, right after loading it, and was read again
right after loading it on this build. For the macOS halves of the same build, see the [notes on
macOS](fm27-steam-macos.md).

## The binary

`game_plugin.dll` as mapped in memory:

| | 26385295 | 26340721 |
|---|---|---|
| Size of image | `0x17CB9000` | `0x1821C000` |
| Link timestamp | `0x6AE8B5A4` | `0x6AE565AF` |

The sections' names were dealt anew, as in every build: the statics the editor uses are in `.xpdata` (read-write),
and the large read-write-execute section is `.ecode`.

## What moved

Every static the editor uses sits 0x11B040 further than in build 26340721, at the same distances from each other:
- the entity arrays: players at `0x5820810`, staff at `0x5820858`, clubs at `0x58209C8`;
- the in-game date's own variable, at `0x57CA3B8`;
- the retirement manager's static, at `0x5812D50`, still 0xDAC0 before the players pair.

With no profile, the code of the released app (0.5.0) found them all by itself: the arrays by scanning, with every
sampled element decoded; the date by searching, as the one of 24 values that read as dates that fitted the contracts
(3,578 of 3,578) and the current injuries (120 of 120); the manager where build 26340721 keeps it from the players
pair, which the search for pointers to it confirmed. All ten checks passed.

## What did not move

The object layout. Before the update, `fmlibre-probe` read the save in full: every player and club as exported, the
lists of staff, loans, bans, retirements and clauses, the statistics of every field the editor reads, and the raw
bytes of 210 objects (100 players with their person blocks and contracts, 60 members of staff, 50 clubs). After the
update, the same probe read the same save again:
- the 47,896 players' 108 fields matched, but for values the new build changed when it loaded the save: 11 squad
  numbers given to players who had none, one release clause's amount and one player's rating at one position;
- the 29,737 clubs' 37 fields matched, but for 14 balances, 2 transfer budgets, 4 reputations (by one point each) and
  7 stadiums the new build names differently (Campus Paris-Saint-Germain is now Campus PSG);
- the lists matched line by line, but for the loan of a player who got a squad number;
- no part of any object moved: every 8-byte value that is not a pointer was where it had been, or, where the game had
  changed it, nowhere near.
